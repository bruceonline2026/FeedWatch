## 一句话说明

客户把 RSS/Atom/JSON Feed 的网址交给我们，我们替他们盯着；**内容变了就主动推送**，
并精确告诉他**哪个字段、从什么变成什么**。

**核心差异**：竞品多数只能报"新增条目"，我们能**检测已有条目被修改**并给出字段级 diff——
新闻更正错字、竞品悄悄改价格，这些都不产生新条目，但恰恰是客户最需要知道的。

### 分层判断标准

| 层 | 回答什么问题 | 变更频率 |
|---|---|---|
| **架构** | 整个项目长什么样 | 很少（季度级） |
| **需求** | 做什么功能、验收标准 | 中（月级） |
| **运营手册** | 怎么一步步做 | 高（跟着平台变化） |
| **决策** | 为什么这么选、为什么排除别的 | 低（决策后很少变） |
| **复盘** | 踩过什么坑、教训是什么 | 追加式 |

⚠️ **常见错误**：把"为什么选 A 不选 B"写进运营手册。
**平台会变（被收购、改费率），手册不会自动更新** —— 一份三个月前正确的手册，今天可能把人导向一个用不了的平台。

## 快速开始（开发者）

```bash
npm install
HOST=127.0.0.1 PORT=3001 PUBLIC_URL=https://api.tiici.com \
  FEEDWATCH_BOOTSTRAP_KEY=<至少32位随机> \
  npm start
curl http://127.0.0.1:3001/health
```

> ⚠️ Bind to `127.0.0.1`, never `0.0.0.0`. Put Nginx (or any reverse proxy) in
> front so TLS, access logs and WAF are not bypassed.

### 测试

```bash
npm test              # 87 项离线测试（5 个套件）
npm run test:live     # 28 项真实源测试（需出网）
```

## 二、为什么快照必须落盘（不能只存内存）

**这是本项目最容易被质疑的设计决定，理由必须写清楚。**

### 不落盘会发生什么

```
客户建监控点 → 跑起来 → 我们发一次补丁 → systemctl restart feedwatch
                    ↓
        内存清空，快照基线没了
                    ↓
    下次检查：diffSnapshots(null, 新快照)
                    ↓
        reason: "first_check"，全部条目报「added」
                    ↓
        客户收到一整片假告警 —— 每个条目都说「新增了」
```

**这不是「丢数据」，是「产生错误数据」** ——
客户会以为网站突然发布了 200 条新内容，而实际上什么都没变。

而且基线一旦丢失，服务就**永远退化成只能报「新增」**的产品：
我们承诺的「告诉你哪个字段从 X 变成 Y」不再成立，
与所有竞品无异 —— 而这正是我们卖的东西。

### 为什么必须存「明文」而不是哈希

字段级 diff 的本质是**回答「旧值是什么、新值是什么」**：

```json
{"field": "title", "changed": true, "old": "Item One", "new": "Item One (PRICE RAISED)"}
```

若只存 `sha256(title)`，哈希**不可逆**，我们只能知道「变了」，
**无法告诉客户变成了什么**。

> 反过来讲：如果只存哈希，产品就退化成了 changedetection.io 这类
> 「这页变了」的提示器 —— 那是我们明确不做的产品定位。

### 这是不是「隐私问题」

需要区分两件事：

| | 结论 |
|---|---|
| 我们**处理**了客户的 feed 内容吗？ | **必然处理** —— 监控服务不抓就没法工作 |
| 这些内容**是不是公开的**？ | **是** —— feed 本身就是公开订阅源，客户自己给的地址 |
| 我们会**主动分析/转卖/分享**吗？ | **不会** —— 代码里没有任何此类路径 |
| 会**关联到具体客户身份**吗？ | 监控点归属 apiKeyId，但 Key 只有哈希，反查不到人 |

**真正的隐私边界是「不与第三方共享、不做画像、不跨客户关联」**，
而不是「不落盘」—— 后者在功能上不可实现（见上）。

⚠️ 但**落盘确实带来一个新责任**：磁盘上的文件必须按敏感数据对待。
见下节。

## 三、落盘文件的处置（已实现）

| 要求 | 实现 | 验证 |
|---|---|---|
| 文件仅属主可读写 | `chmod 600` | `scripts/persistence-regression.js` 有断言 |
| 目录仅属主可进出 | `chmod 700` | 同上 |
| 写入原子 | 临时文件 → `fsync` → `rename` | 不存在半截 JSON |

| 损坏不静默丢弃 | 另存为 `.corrupt-<时间戳>` | 有测试 |

**已修正为 600 并加了测试锁住。** 这个案例说明：
**权限问题是静默的 —— 没有报错、没有告警，只有主动检查才能发现。**

## 四、数据生命周期

### 随监控点删除而删除

`DELETE /v1/monitors/{id}` 会同时删除该监控点**及其快照**
（`deleteMonitor` 内调用 `snapshots.delete(id)`，见 `src/service.js`）。

**客户可自助删除全部数据**：删掉所有监控点即删掉全部 feed 内容，
只剩 API Key 的哈希（无法反推明文，也无法关联到人）。

### 长期保留

| 数据 | 保留策略 | 理由 |
|---|---|---|
| 统计事件 JSONL | **无自动清理** ⚠️ | 见下方待办 |
| API Key 哈希 | 长期 | Key 需长期有效 |

⚠️ **已知缺口**：`events-*.jsonl` **没有自动轮转与清理**。
虽然里面只有聚合计数（不含客户内容），但文件会无限增长。
**待办**：加保留期（如 180 天）或总量上限。

## 五、备份要求

| 数据 | 丢了会怎样 | 是否值得备份 |
|---|---|---|
| `store.json` | **客户监控全部丢失 + 重启后一片假告警** | ✅ **必须备份** |
| `events-*.jsonl` | 丢失经营统计（不影响客户） | 建议备份 |
| `/etc/feedwatch/env` | **服务锁死**（引导密钥丢失） | ✅ **必须备份** |

⚠️ **当前未配置任何备份任务** —— 这是明确的缺口。
单机部署下服务器损坏 = 所有客户数据永久丢失。

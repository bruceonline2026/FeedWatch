## 二、根因

### 直接原因
`C:\inetpub\wwwroot\web.config` 中**已存在**：
```xml
<staticContent>
    <mimeMap fileExtension="." mimeType="text/plain" />
</staticContent>
```

我又往全局 `applicationHost.config` 加了**同样的** `mimeMap fileExtension="."`。

**IIS 的 staticContent 配置是「站点级继承 + 全局叠加」** —— 同一个 `fileExtension="."` 在两层各定义一次，
导致静态内容模块初始化失败 → 所有请求 500。

### 为什么这是我的错：技能文档里已经写了

`iis-acme-cert` 技能第 5 条硬性禁忌明确写着：

> **无扩展名 ACME token 文件需要 `mimeMap fileExtension="." mimeType="text/plain"`（IIS 默认拒绝无扩展名文件）**

但我**没查各站点是否已有这条配置**，就直接往全局加。技能文档同时写了 2026-10-01 的同类事故记录，
**我读到了却没对照自己的操作**。

### 为什么 www 是 500 而 api/game 正常

| 站点 | 站点级 web.config 有 mimeMap | 结果 |
|---|---|---|
| Default Web Site（www/tiici.com） | ✅ 有 | ❌ **冲突 → 500** |
| API（api.tiici.com） | ❌ 无（且我建错了目录） | ✅ 正常 200 |
| WordMaster（game.tiici.com） | ❌ 无 | ✅ 正常 200 |

**只有已有站点级配置的 www 才会冲突** —— 这是我事先没想到的。

## 三、我犯的三个错误

### 错误 1：没有先查现状就改全局配置

正确顺序应是：**先逐站点查 `web.config` 有没有 mimeMap → 只给缺的站点加站点级配置 → 绝不动全局**。

### 错误 2：把「误建目录」误判为「数据丢失」

诊断时看到 `C:\WebServer\wwwroot` 只有我建的 `.well-known`，我一度判断「原有文件被覆盖」。
实际上真实路径是 `C:\inetpub\wwwroot`，**文件一直都在**。

**教训**：判断「数据丢失」前必须**先确认站点的真实物理路径**（`Get-Website` 的 `PhysicalPath`），
不能凭目录名猜测。

### 错误 3：反复用不存在的 API 而不查文档

连续 3 次凭记忆调用 API：`GetStaticContentSection()`（不存在）、`Set-WebConfigurationProperty -Section`（参数名错）、
`$_.BindingInformation` 经 SSH 返回空。**每次都是"先写后试"，浪费 6 轮。**

**教训**：Windows 管理接口的 API 名称必须实际枚举确认，不能凭印象。

## 五、正确的修复方案（尚未执行，待徐总确认后按此执行）

**不给全局加 mimeMap，改为给缺配置的站点加站点级 web.config：**

| 域名 | 站点 | 是否需加站点级 mimeMap |
|---|---|---|
| api.tiici.com | API | ✅ 需要 |
| game.tiici.com | WordMaster | ✅ 需要 |
| www.tiici.com | Default Web Site | ❌ 已有，勿动 |

写入方式：在对应 `web.config` 的 `<system.webServer>` 下加
```xml
<staticContent>
    <mimeMap fileExtension="." mimeType="text/plain" />
</staticContent>
```
**不碰 `applicationHost.config`**，因此不可能与任何站点冲突。

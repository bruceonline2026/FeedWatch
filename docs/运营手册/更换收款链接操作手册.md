# 更换收款链接（Payoneer 单次链接的日常操作）

**最后更新**：2026-10-17

---

## 一句话背景

Payoneer 的收款链接**每条只能用一次**。官方原文：

> Each link is **single-use**: it's tied to one buyer and one transaction.
> **Once it's paid, the link can't be reused.**

所以「把链接直接写进落地页」是错的 —— 收第一笔钱链接就作废，
之后任何客户点付费按钮都会看到：

```
That payment link was already paid
```

> ⚠️ **这比没有付款入口更糟** —— 客户会怀疑你是个不靠谱的卖家。

---

## 现在怎么解决的

```
落地页按钮  →  https://api.tiici.com/pay   ← 永不改变
                    ↓ 302 跳转
服务器 /opt/feedwatch/pay-link.json 里的当前有效链接
                    ↓
              Payoneer 付款页
```

**所以落地页、README、推文里印的 URL 永远不用改。**

链接用完 → 只改服务器上**一个文件**。

---

## 你要做的（换新链接，约 1 分钟）

### 第 1 步：在 Payoneer 后台建新链接

```
收款 → 创建收款链接
```

| 字段 | 填什么 |
|---|---|
| **链接名称** | `FeedWatch Pro — $29/12 months` ← ⚠️ 别写 `$29/month`，实际是 12 个月一次付 |
| 金额 | 固定 `29.00` USD（最低 $20）|
| 到期日期 | `2027-10-16`（一年，别用默认的 3 个月）|
| 手续费承担方 | **Recipient**（你承担 3%）→ 客户实付正好 $29 |
| **描述** | 见下方**「描述文案（直接复制）」** |

### 描述文案（直接复制，2026-10-17 实测可用）

```
FeedWatch Pro subscription. 25 monitors, hourly checks, field-level diffs. Get your API key at api.tiici.com
```

**照抄这一行即可。** 它是实测过后**没被 Payoneer 拒绝**的版本。

⚠️ **为什么长得这么朴素**（不是随便写的，是踩过坑）：

| 写法 | 结果 |
|---|---|
| `https://api.tiici.com/` | ❌ **被拒** —— 双斜杠可能触发符号黑名单 |
| `Slack/Discord` | ❌斜杠同样有风险 |
| `api.tiici.com`（无协议）| ✅ **通过** |
| `Slack and Discord` | ✅ 通过 |

Payoneer 描述字段的**禁用符号**（实测报错原文）：
`* # ^ & ; [ ] { } ? < > ~ \` `

→ **写文案只用字母、数字、空格、逗号、句点**，最保险。

⚠️ **注意描述里的数字要和落地页一致**：
「25 monitors · hourly checks」必须与落地页 Pro 档一致
（落地页另有「or every 15 minutes」，描述里不必展开，保持简洁）。

> 🔗 **同一个数字要出现在三个地方**：Payoneer 后台链接名/描述、
> 落地页 Pro 档、退款政策。三处不一致就是「只声明不强制」，
> 客户会怀疑自己看错了价格。

## 🔗 链接池（2026-10-17 加：备用量）

**为什么要池，不是一条**：验证期 0-5 个客户，**连续来两个就会撞链**。
一次备 2-3 条，就能「一个被用过 → 把下一条挪到 current」，
不必每次现建（建一次要填 5 个字段，还容易踩符号黑名单）。

### 查看还剩几条

```bash
# 需要一把 Key（自助领的那把就行）
curl -s https://api.tiici.com/v1/pay-links -H "x-api-key: 你的Key"
```

返回：

```json
{ "has_current": true, "standby_count": 2, "total": 3, "needs_new_link": false }
```

⚠️ **`needs_new_link: true` = 该建新链接了**（current 用完且没有备用）。

> 这端点在**鉴权区之内**且**只返回数量、不返回 URL** ——
> 否则等于把备用链接送给任何拿到 Key 的人。

### 配置文件格式

```json
{
  "current": "https://link.payoneer.com/Token?t=第一条&src=pl",
  "standby": [
    "https://link.payoneer.com/Token?t=第二条&src=pl",
    "https://link.payoneer.com/Token?t=第三条&src=pl"
  ],
  "note": "Payoneer single-use links. current is used first; when it is consumed, move the first standby entry into current.",
  "updated": "2026-10-17"
}
```

`/pay` 只跳 `current`。**`standby` 不会被自动使用** —— 因为死链与活链
的 HTTP 响应完全相同，**程序无法判断 current 是否已作废**，
所以「挪动」这一步必须人工做。

### 一条链接被用掉后怎么办

```bash
ssh feedwatch-vultr
sudo nano /opt/feedwatch/pay-link.json
```

把 `standby` 的第一条挪到 `current`，其余后移：

```json
{
  "current": "<原来 standby 的第一条>",
  "standby": ["<原来 standby 的第二条>", "<新建的链接>"]
}
```

**改完立即生效，不用重启服务**（每次请求都重读文件）。

验证：

```bash
curl -s -o /dev/null -D - https://api.tiici.com/pay | grep -i location
```

## ⚠️ 更省事的做法：**去问能不能开可复用链接**

Payoneer 官方说 reusable link 支持 "subscription-style billing"，
一个链接收所有人 —— **那样整个池都不需要了**。

但标注 **subject to eligibility（需符合资格）**，个人账户不一定能过。
**要问客服才知道。**

## 🔑 自助取 Key（`/get-key`，2026-10-17 加）

**为什么做**：落地页的「Start free」原本跳到三步接入**说明**，
徐总指出**用户点「免费开始」看不到 Key 就走了**。

现在：填一个邮箱 → **立刻**拿到 Key。**无注册、无密码、无信用卡。**

```bash
# 看页面
curl -s https://api.tiici.com/get-key | head -5

# 领一把（自己也可以用这个入口测）
curl -s -X POST https://api.tiici.com/get-key \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "email=you@example.com" | grep -oE 'fw_[0-9a-f]{32}'
```

### 三层防护（少一层就是无限 Key 机器）

| 层 | 限制 | 挡什么 |
|---|---|---|
| ① | 邮箱格式校验 | 明显的脚本 |
| ② | **同 IP 5 把/小时** | 单 IP 批量 |
| ③ | **全站 60 把/天** | 换 IP / 分布式 |

超出返回 **429 + 明确文案**（不是静默失败），并提示改发邮件。

### ⚠️ 两个必须知道的限制

1. **自助签发的 Key 不能签发新 Key** —— D8 门控对它照样生效（403）。
   它只能建监控点、查 feed。
2. **Key 在内存里，重启即失效** —— D7（Key 吊销）还没修，这是同一个根因。
   客户反馈「Key 突然不能用」时，先查是不是重启过。

### 客户付款后要不要换 Key？

**自助 Key 只绑「免费层」配额**（5 个监控点），与付费无关。
客户付了 $29 之后，**要不要额外给他一把更高配额的 Key**
目前没有自动机制 —— 你看到付款后手工签一把给他即可
（走 `/v1/apikeys`，用引导密钥调用）。

## 万一忘了换会怎样

| 情况 | 表现 |
|---|---|
| 链接已用完 | 客户看到 Payoneer 的 "already paid" 页 |
| **配置文件被删/格式错** | 客户看到 **503 提示页**（友好文案 + 你的邮箱），不会白屏 |

⚠️ **死链与活链的 HTTP 响应完全相同**（都是 302），
所以**系统无法自动检测链接是否作废**，也没有自动告警。

> 💡 想彻底解决，去 Payoneer 问客服能否开通
> **可复用链接（reusable link）** —— 官方说该功能
> "subject to eligibility"（需符合资格），个人账户不一定能过。

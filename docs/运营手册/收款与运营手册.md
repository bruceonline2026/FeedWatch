# 运营维护手册（初版）：什么时候付费、在哪配置、在哪收款

> 版本：v1.0 · 2026-10-12
> 覆盖：RSS 变更监控 API 试水阶段的完整运营流程
> 三个核心问题：**用户什么时候付费 · 哪里配置 · 在哪里收款**

---

## 第零部分：先把三件事的关系搞清楚

```
用户为什么要付费       →  他需要一个他做不到或不愿做的东西
     ↓
什么让他愿意当场付钱   →  免费额度用完 / 免费层解决不了他的问题
     ↓
在哪配置               →  定价页 + 支付页（你的站点）+ 服务端后台（你）
     ↓
在哪收款               →  Lemon Squeezy（起步）→ Paddle（扩张）→ Stripe（月入 5万+）
```

**核心认知：试水阶段的第一笔钱不需要走 Stripe，也不需要公司主体。**
先让付款流程跑通，再优化成本——反过来会卡死。

---

# 第一部分：用户什么时候付费

## 1.1 四个付费触发点（按发生概率排序）

### 触发点一：免费层额度用完（占比最高，约六成）

**用户行为**：注册免费层，配了 3 个监控点，用了几天，发现不够用。

**为什么会发生**：免费层的限制必须是**真实用得上就会撞到**的：

| 限制项 | 免费层 | 用户撞到的瞬间 |
|---|---|---|
| 监控点数 | 3 个 | "我第四个源加不上了" |
| 检查频率 | 24 小时 | "我的告警慢了 24 小时，错过了窗口" |
| 变更历史 | 不保留 | "我想查上周那次变更，改了什么" |

⚠️ **设计原则**：免费层要能完整体验核心价值，**但必须撞得到墙**。
**如果用户一个月都用不满免费层，说明定价太松，他会永远不付费。**

### 触发点二：免费层解决不了他的场景（约三成）

**用户行为**：他在免费层里试过了，但需求超出范围。

| 场景 | 免费层不够用在哪 | 升级到哪个档 |
|---|---|---|
| 安全团队盯 20 个组件的 CVE | 3 个点不够 | Starter 25 个 |
| 需要 1 小时级告警 | 免费层 24 小时太慢 | Pro |
| 要查历史变更做审计 | 免费层不保留 | Pro / Team |
| 监控 200 个竞品页面 | 任何个人档都不够 | Team 500 个 |

### 触发点三：多人协作需要（约一成）

**用户行为**：一个人配好了，团队里其他人也要用。

**当前 MVP 没有这个功能** → 这类用户要么等，要么走 Pro 的用量。

### 触发点四：量超额（后续阶段才有）

按量计费客户超出配额后自动计费。**试水阶段不做这个。**

## 1.2 付费的时机判断（一条原则）

> **不要在用户第一次使用时推销，要在用户撞到墙时推销。**

具体做法：

| 场景 | 你的动作 |
|---|---|
| 用户注册免费层 | **不推销任何东西**，只说"用起来有问题来找我" |
| 用户创建第 4 个监控点失败 | **返回错误信息里带一句**：需要更多额度，可升级 |
| 用户达到 30 天使用期 | 发一封邮件：本期已用 X 次，你监控了 Y 个源 |
| 用户主动问"能不能多配几个" | **这时候报价**，他已经在问你价格了 |

⚠️ **免费层不做任何主动推销。** 早期推销是最快的卸载方式。

## 1.3 免费层到底给多少（用真实数据决定）

**初始设定**（上线前用这个）：

| 项 | 免费层 |
|---|---|
| 监控点数 | 3 个 |
| 检查频率 | 24 小时 |
| 保留历史 | 0 天 |
| 每日检查配额 | 50 次/天 |

**上线后必须调整的规则**：

> **每两周看一次数据**：如果 90% 以上的免费用户都用不满配额 → **限制太松，迟早没人付费**
> 如果 100% 的用户第一天就撞墙 → **限制太紧，会劝退潜在付费用户**
> 目标是：**大部分免费用户会在 3–14 天内自然撞到墙**

## 1.4 定价档位与何时推哪个

| 档 | 月费 | 监控点 | 频率 | 什么时候推给谁 |
|---|---|---|---|---|
| Free | $0 | 3 | 24h | 所有人 |
| **Starter** | **$9** | **25** | **6h** | 免费层不够用，且只是个人用 |
| **Pro** | **$29** | **100** | **1h** | 需要小时级、需要历史、团队用 |
| Team | $79 | 500 | 15min | 监控大量源、有 SLA 要求 |

**升档话术**（在用户撞墙的那一刻说）：

> "你现在的 3 个监控点已经用满了，而且 24 小时一次的频率对你的场景偏慢。
> Starter 档 $9/月给你 25 个监控点、6 小时一次，**比现在的速度快 4 倍**。"

**关键：把"升级"说成"解决问题"，不是"请你多付钱"。**

# 第二部分：哪里配置

## 2.1 配置分两处，别搞混

| 配置什么 | 在哪配 | 谁来配 |
|---|---|---|
| **服务档位、价格、货币** | Lemon Squeezy 后台 | 你 |
| **功能开关、限额、监控点规则** | 你自己的服务后台 + 数据库 | 你 |
| **用户的支付信息、订阅状态** | Lemon Squeezy 后台（自动同步） | 客户（自助） |
| **用户的 API Key** | 你自己的站点 | 客户（自助） |

⚠️ **一个原则：凡是客户能自己改的，都做成自助；凡是需要你手动操作的，收款平台都做不到。**

## 2.2 定价配置在哪改（Lemon Squeezy 后台）

**入口**：Lemon Squeezy → Store → Products

**要建四个产品变体（Variant）**：

```
① Free     $0     → 只是显示用，不实际售卖
② Starter  $9     → 月付订阅
③ Pro      $29    → 月付订阅
④ Team     $79    → 月付订阅
```

**每个变体的配置项**：

| 配置项 | 怎么填 |
|---|---|
| 名称 | Starter / Pro / Team（不要叫"Basic""Premium"，客户看不懂） |
| 价格 | 9 / 29 / 79 USD |
| 计费周期 | Monthly |
| **产品用途描述** | 见下方文案模板 |

**产品描述模板**（直接可用）：

```
Starter — 25 monitors · 6-hour checks

Monitor up to 25 RSS/Atom/JSON feeds and get a webhook
notification within 6 hours of any change — new items, edited
titles, or modified content.

Includes field-level diff so you know exactly what changed.
```

⚠️ **注意 Lemon Squeezy 底层用的是 Stripe 处理支付**，但它在上层加了"商家代表"层（代收代缴全球税），所以**你不需要自己注册 Stripe 也能收款**。

## 2.3 功能配置在哪改（你的服务后台）

**需要你自己实现的配置项**：

| 配置项 | 存储位置 | 说明 |
|---|---|---|
| 监控点 | 数据库表 `monitors` | url / interval / keywords / extract 配置 |
| 用户与套餐 | 数据库表 `subscriptions` | 从收款平台 webhook 同步 |
| API Key | 数据库表 `api_keys` | hash 存储，明文只显示一次 |
| 变更历史 | 数据库表 `changes` | 保留 30 天（Pro/Team） |
| 配额计数器 | Redis（按天过期） | 免费层每日 50 次 |
| 投递记录 | 数据库表 `deliveries` | 推送结果、失败重试记录 |

**关键：套餐状态从 Lemon Squeezy webhook 来，不要让客户自己填。**

需要监听的 webhook 事件：

| 事件 | 你的动作 |
|---|---|
| `subscription_created` | 开通 Pro 权限 |
| `subscription_updated` | 升降档同步 |
| `subscription_cancelled` | 降回免费层，但**不要立即断服务** |
| `subscription_payment_failed` | 标记欠费，发提醒邮件，给 7 天宽限 |
| `order_created` | 记录首次购买 |

⚠️ **重要设计决定**：`subscription_cancelled` 时**不要立刻断服务**。
立即断会引发大量投诉和差评。给 30 天宽限期，期间只读不监控。

## 2.4 客户端集成配置（客户的 webhook 接收）

**客户要在他自己系统里配一个接收地址**，你要告诉他的模板：

```json
POST https://客户的系统/webhook
Headers:
  Content-Type: application/json
  X-Webhook-Signature: sha256=...

{
  "monitor_id": "mon_a1b2c3",
  "change_type": "added|modified",
  "item_id": "...",
  "title": "...",
  "diff": [
    { "field": "title", "old": "...", "new": "..." }
  ],
  "link": "https://原文链接",
  "detected_at": "2026-10-12T02:07:11+08:00"
}
```

**客户侧的验证代码模板**（要提供给他）：

```python
import hmac, hashlib

def verify(raw_body: bytes, header_signature: str, secret: str) -> bool:
    expected = "sha256=" + hmac.new(
        secret.encode(), raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, header_signature)
```

⚠️ **必须提供这段代码。** 不提供的话，客户不会验证签名，你的服务就是一个可被伪造的开放端点。

## 2.5 配置错误排查表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 用户付了钱但套餐没开通 | webhook 没收到或没处理成功 | 查 webhook 日志，手动补开通 |
| 用户升档了但限流没变 | 缓存未失效 | 套餐变更时清 Redis |
| 用户取消后仍在扣费 | 没监听取消事件 | 补 webhook |
| 推送发不出去 | 客户 webhook 端点失败 | 重试 3 次后邮件告警 |
| 显示的用量不准 | 计数上报失败 | 加重试队列（见第五部分） |

## 3.1–3.6（以下内容已作废，仅保留作为历史参考）

> ⛔ **已核实（2026-10-12）：中国大陆主体不在 Lemon Squeezy 卖家支持名单内，不能用。**
> 官方收款说明：`docs.lemonsqueezy.com/help/getting-started/getting-paid`

## 3.1 起步期选 Lemon Squeezy（❌ 已作废，中国大陆主体不适用）

**为什么起步选它，不选 Stripe**：

| | Lemon Squeezy | Stripe |
|---|---|---|
| 费率 | 5% + $0.50 | 2.9% + $0.30 |
| $5,000/月时每笔 | $1.50（7.5%） | $0.88（4.4%） |
| **税谁处理** | **平台全包** | **你要自己在 50 个税区注册申报** |
| 拒付 | 平台处理 | $15/笔自理 |
| 到账 | 约 7 天 | 约 2 天 |
| 30 分钟内能收款 | ✅ | 需要先做税务合规 |

**核心判断**：省下的那 3% 需要用"处理 50 个税区的税务注册与申报"的时间来换。

> **月收入 < $1 万，选 Lemon Squeezy。** 这个判断来自多份 2026 年的实测对比，结论一致。

**它的三个优势（起步期最有用）**：
1. **税务合规内建** —— 不用为了收欧洲的钱去注册 VAT
2. **客户门户自带** —— 用户能自己看账单、改卡、取消，你不用做
3. **内置联盟营销** —— 可以让推广者带客户并分成

**已知限制**：**不支持按量计费（usage-based billing）。** 我们的 MVP 是固定月费，暂时不影响。

## 3.2 三个阶段的钱怎么走

| 阶段 | 月收入 | 用什么 | 为什么 |
|---|---|---|---|
| **试水期** | 0 – $1万 | **Lemon Squeezy** | 快、省心、无税务负担 |
| **扩张期** | $1万 – $5万 | **Paddle** | 支持按量计费、内置催款与流失分析、企业采购流程 |
| **规模化** | $5万+ | **Stripe** | 费率省约 3%，且唯一支持 Connect 分账 |

⚠️ **迁移很痛苦**：从 Lemon Squeezy 迁到 Stripe 需要迁移全部订阅，且**客户要重新填支付信息**。所以起步就选会迁移的那个（Lemon Squeezy 底层就是 Stripe，会平滑一些）。

## 3.3 收款链接怎么给客户

### 方案 A：定价页放按钮（MVP 阶段用这个）

在定价页每个档位放一个按钮：

```
Free    $0     [免费开始]
Starter $9     [升级到 Starter]  → 跳转 Lemon Squeezy 结账页
Pro     $29    [升级到 Pro]      → 跳转结账页
Team    $79    [联系销售]
```

### 方案 B：邮件里给专属链接（转化最高）

用户在免费层撞墙后，你发一封邮件：

> 你的 3 个监控点已用满。
>
> 升级 Starter（$9/月）→ 25 个监控点 + 6 小时检查频率
>
> [点这里升级]（这是你的专属链接）

**专属链接的价值**：用户点了就跳到已填好产品的结账页，**不用再选**。转化率差异很大。

## 3.4 收款前的四项准备工作

| # | 准备什么 | 说明 |
|---|---|---|
| 1 | **收款账号** | Lemon Squeezy 支持 PayPal 和银行转账（Payoneer / Wise 等） |
| 2 | **身份验证** | 需要提交身份证明与地址证明，**提前准备，别卡在这里** |
| 3 | **产品已建好** | 四个变体配置完成、描述写好 |
| 4 | **结账页测试** | **用测试模式完整走一遍**，确认能付款、能收到 webhook |

⚠️ **第 4 条不能省。** 上线前必须确认：付款成功 → webhook 收到 → 套餐开通 → 限流放宽，四步全部打通。

## 3.5 钱的实际流转路径

```
客户点击购买
   ↓
跳转 Lemon Squeezy 结账页（你不在这个页面上，平台是商家）
   ↓
平台代收客户的钱 + 代收代缴当地税（VAT/GST/销售税）
   ↓
平台给你发一封"结算单"，客户看到的是平台的收款方
   ↓
约 7 天后，按你配置的收款方式到账
```

⚠️ **客户信用卡账单上显示的是 Lemon Squeezy，不是你的公司名。** 这是商家代表模式的代价——好处是你不用承担税务与合规，坏处是客户不清楚在跟谁买。

**这一点要在 FAQ 里写明**，避免客户以为是诈骗。

## 3.6 按量计费（后续阶段，现在不做）

如果将来要按 API 调用次数收费：

- **Stripe 用 Meters**（不是老版的 `createUsageRecord`，那个已在 2025 年废弃）
- **Paddle 原生支持按量计费**
- **Lemon Squeezy 不支持** —— 这是它的一个硬限制

⚠️ **Stripe Meters 的三个坑**（实测）：

1. **测试模式和正式模式的 Meter 是独立对象** —— 测试配的不会带过去，正式环境要重新建
2. **event_name 是精确匹配** —— 拼错不会报错，会**静默不计数**
3. **上报失败要重试队列** —— 失败就是漏计的收入。**绝不能只 console.error 了事**

**MVP 阶段不做按量计费**，固定月费更简单，也避免踩这些坑。

# 第五部分：故障与异常处理

## 5.1 推送被客户投诉"漏报了"

**排查顺序**：
1. 该监控点抓取是否失败（看日志）
2. 变化是否真的产生了 diff（看哈希对比记录）
3. 投递是否失败（看投递记录和重试）

**如果确认是我方漏报**：
- **立刻主动告知客户，不要等他自己发现**
- 补推变更记录
- 记入反馈表，转化为需求

## 5.2 客户说"没收到推送"

**最常见原因（按概率）**：
1. 客户没有验证 HMAC 签名，把合法的推送当成伪造的丢弃了 → **这占大多数**
2. 客户系统防火墙拦了
3. 客户 webhook 返回非 2xx，重试 3 次后放弃了
4. 客户填错了接收地址

**处理**：先问"你的接收端有日志吗"，多数情况一看就知道。

## 5.3 付款失败

| 情况 | 处理 |
|---|---|
| 卡片被拒 | 平台会邮件通知客户，引导更新支付方式 |
| 订阅扣费失败 | **不要立即断服务**，标记欠费 + 邮件提醒 + 7 天宽限 |
| 客户要求退款 | 通过平台处理（Lemon Squeezy 会处理税的部分） |

⚠️ **宽限期的重要性**：立即断服务是最容易引发差评和投诉的做法。**收入 $9 vs 口碑损失，不值得。**

## 5.4 客户问"数据能导出吗"

**必须能**。这是信任基础。
MVP 阶段提供 CSV 导出；后续版本提供 API 导出。
**这一条写进服务条款，不要留到出问题才处理。**

## 📌 补充：国内跨境收款平台对照（同日补充）

**⚠️ 重要纠正：PingPong / WorldFirst 万里汇 / 连连国际 / 网商银行跨境通都是面向跨境电商交易设计的，不是为订阅制 SaaS 设计的。** 多家测评文档明确写："无订阅管理和用量计费产品，对 SaaS 支撑有限"。

**国内相对适配的只有两家**：

| | Airwallex 空中云汇 | Payoneer Checkout |
|---|---|---|
| 费率 | 2.5–3.5% + 通道费 | 2.9% + 通道费 |
| **个人主体** | ❌ **仅企业** | ✅ 可开通 |
| 开通时间 | 5–10 工作日 | **1–3 天** |
| VAT 代缴 | ❌ 自己处理 | ❌ 自己处理 |
| 订阅管理 | 有"全球计费管理" | ❌ 需自研 |

**分阶段建议**：
1. **MVP 期（0–5 付费用户）→ Payoneer Checkout**（个人可开、1–3 天不阻塞开发）
2. **有公司主体后 → Airwallex**（费率更低、有订阅功能、有中国大陆牌照）
3. **月入 $5,000+ → 评估 Stripe Atlas**（⚠️ Stripe 无内地支付资质，国内公司必须走海外主体）

**三条合规事实**：① **个人年度境外收入超 12 万人民币需自行申报缴税**（平台不代办）② Airwallex/Payoneer 只解决"收钱"，VAT 要自己扛 ③ 各平台收汇需按外汇管理规定申报

**详见《国内跨境收款平台对照与订阅收款选型.md》**

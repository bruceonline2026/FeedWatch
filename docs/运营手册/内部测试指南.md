## 零、先准备一把 Key

```bash
# 从服务器取引导密钥（仅内部用）
KEY=$(ssh feedwatch-vultr 'sudo grep -oP "FEEDWATCH_BOOTSTRAP_KEY=\K.*" /etc/feedwatch/env')

# 签一把测试 Key（模拟给客户发的那把）
TEST=$(curl -s -X POST https://api.tiici.com/v1/apikeys \
  -H "Content-Type: application/json" -H "x-api-key: $KEY" \
  -d '{"label":"内部测试-2026-10"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["key"])')

echo "$TEST"   # 复制保存，明文只显示这一次
```

> ⚠️ 签发限流：**3 把/分钟 + 20 把/天**。连续签发会撞 429，等一分钟即可。

## 一、完整测试流程（已实测跑通，2026-10-16）

### 步骤 1 · 查看配额

```bash
curl -s https://api.tiici.com/v1/usage -H "x-api-key: $TEST"
```

**实测返回**：
```json
{"plan":"free","monitors":0,
 "limit":{"monitors":5,"frequency":["6h"],"checks_per_day":20},
 "usage":"MVP 阶段为内存统计，生产环境将接入持久化"}
```

---

### 步骤 2 · 创建监控点（免费层 5 个上限）

```bash
add() {
  curl -s -X POST https://api.tiici.com/v1/monitors \
    -H "Content-Type: application/json" -H "x-api-key: $TEST" \
    -d "{\"name\":\"$1\",\"url\":\"$2\",\"intervalSeconds\":21600}"
}

add "Node.js Releases" "https://github.com/nodejs/node/releases.atom"
add "Hacker News"     "https://hnrss.org/frontpage"
add "Cloudflare 博客"  "https://blog.cloudflare.com/rss/"
```

**实测**：三个都建成，返回 `mon_xxx` 形式的 id。

---

### 步骤 3 · 立即触发抓取（**不用等 6 小时调度**）

```bash
curl -s -X POST "https://api.tiici.com/v1/monitors/<mon_id>/check" -H "x-api-key: $TEST"
```

**实测结果**（三种协议全通）：

| 监控点 | format | 变更数 | reason |
|---|---|---|---|
| Node.js Releases | `atom` | 10 | `first_check` |
| Hacker News | `rss` | 20 | `first_check` |
| Cloudflare 博客 | `rss` | 20 | `first_check` |

---

### 步骤 4 · 验证「不误报」（**这一步最关键**）

对同一个监控点再抓一次：

```bash
curl -s -X POST "https://api.tiici.com/v1/monitors/<mon_id>/check" -H "x-api-key: $TEST"
```

**实测**：
```json
{"changed":false,"format":"atom","change_count":0,"raw_change_count":0,"reason":"hash_match"}
```

**`hash_match` = 哈希一致，直接跳过逐字段比对。**
这是「不产生抖动误报」的证据 —— **没有这一条，客户会被噪音淹没而退订**。

---

### 步骤 5 · 查看单个监控点详情

```bash
curl -s "https://api.tiici.com/v1/monitors/<mon_id>" -H "x-api-key: $TEST" | python3 -m json.tool
```

**实测返回**（重点看这几个字段）：
```json
{
  "status": "active",                    // 调度状态（用户意图）
  "last_check_ok": true,                 // 上次抓取是否成功
  "error_count": 0,                      // 连续失败次数
  "tripped_by_circuit_breaker": false,   // 熔断标记（独立于 status）
  "next_check_at": "2026-10-16T04:38:10.370Z"
}
```

> ⚠️ **`status` 与 `tripped_by_circuit_breaker` 是正交的**：
> `status` 只表达用户意图（active/paused），熔断用独立标记。
> 这样才能区分「用户主动暂停」与「系统自动熔断」，恢复路径不同。
> 详见 `docs/复盘/状态字段语义.md`。

  -H "Accept: application/json, text/event-stream" \

### 步骤 8 · 清理

```bash
for id in $(curl -s https://api.tiici.com/v1/monitors -H "x-api-key: $TEST" \
           | grep -oE "mon_[a-f0-9-]+" | sort -u); do
  curl -s -o /dev/null -w "删除 $id: %{http_code}\n" \
    -X DELETE "https://api.tiici.com/v1/monitors/$id" -H "x-api-key: $TEST"
done
```

## 四、测试环境注意

| # | 事项 | 说明 |
|---|---|---|
| 1 | **内存存储，重启清空** | 所有监控点和快照在内存里。`sudo systemctl restart feedwatch` 后全丢 —— **这不影响 Key**（Key 也重存，要靠引导密钥重新 seed）|
| 2 | **Key 也随重启失效** | 只存哈希，重启后 seed 不回来 → **重启前通知所有客户**（D7 修好前的已知代价）|
| 3 | **抓取需出网** | 本机（Mac）测不出「能否抓境外源」，**必须在服务器上测**。这正是「境外 VPS」方案要解决的问题 |
| 4 | **免费层频率只有 6h** | 想测 15 分钟/1 小时需改 `/etc/feedwatch/env` 的 `FREE_INTERVALS` 并重启 |

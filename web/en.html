Know when a feed changes, not just grows

Most monitoring tools can only tell you a new item appeared. But a corrected typo, a quietly raised price, a reworded policy clause — these are edits to existing items. They produce no new item, so they get missed. FeedWatch detects them and reports field-level diffs.

Three steps to integrate

Use the REST API or MCP — both run on the same core logic.

1

Create a monitor

Submit an RSS / Atom / JSON Feed URL and pick a check frequency (15 min / 1 h / 6 h).

2

We fetch and diff on a schedule

Each round starts with a hash prefilter — unchanged feeds cost nothing. Only on a change do we diff field by field, so ordering jitter produces no false alarms.

3

Changes are pushed

Via signed webhook (HMAC, with retries), or straight to Slack / Discord.

Capabilities

Everything below is live and verified in production — not a roadmap.

Field-level diffs

Six fields compared individually; changes push with old / new values. Long bodies are sent as a hash plus a length delta.

Three protocols

RSS 2.0 (including RDF), Atom 1.0 and JSON Feed 1.1 — auto-detected.

REST + MCP

Two entry points on one core, so the maintenance cost barely grows.

Signed webhooks

HMAC-SHA256 signature header, with 3 automatic retries (1s / 5s / 15s backoff).

Keyword filtering

Only alert on items matching your keywords, in title or body.

SSRF hardening

DNS pinning with per-hop revalidation. Private ranges and cloud metadata addresses are rejected — for feed fetches and webhook delivery alike.

FAQ

Do I need to host anything?

No. One API key and you are done — RSS, Atom and JSON Feed all work.

How noisy is it?

A hash prefilter skips unchanged feeds entirely, and a second fetch of an unchanged feed reports changed: false. Ordering jitter does not count as a change.

Do you store my data?

Only a hash of each API key — plaintext is shown once at creation and never written to disk. Feed bodies are processed in memory and discarded.

What are the current limits?

Monitors are held in memory during the validation stage, so a restart clears them. Persistence arrives later.

知道 Feed 变了，而不只是变多了

多数监控工具只能告诉你「新增了一条」。 但新闻更正错字、竞品悄悄改价格、政策条款被微调 —— 这些都是已有条目被修改， 不产生新条目，因此被漏掉。FeedWatch 检测这类修改，并给出字段级 diff。

创建监控点

2

我们定时抓取比对

所有请求走 https://api.tiici.com，鉴权用 x-api-key 头。

创建监控点 
# 创建监控点
curl -X POST https://api.tiici.com/v1/monitors \
  -H "x-api-key: $FEEDWATCH_KEY" \
  -H "content-type: application/json" \
  -d '{
    "name": "竞品定价页",
    "url": "https://example.com/pricing.atom",
    "intervalSeconds": 3600,
    "keywords": ["price", "pricing"]
  }'
# 立即检查一次（不必等调度）
curl -X POST https://api.tiici.com/v1/monitors/mon_xxx/check \
  -H "x-api-key: $FEEDWATCH_KEY"

# →
{ "changed": true, "format": "atom",
  "change_count": 1,
  "changes": [{ "change_type": "modified",
    "title": "Starter",
    "diff": [{ "field": "title",
                 "old": "Starter", "new": "Starter (New Pricing)" }] }] }
# Webhook 收到的载荷
{
  "event": "feed.changed",
  "monitor_id": "mon_xxx",
  "url": "https://example.com/pricing.atom",

常见问题

它和普通的 RSS 监控工具有什么区别？

核心差异在「修改检测」。多数工具对比条目 id 集合，只有新增或消失才告警。 而 FeedWatch 会把已有条目的 6 个字段逐个比对，值变了照样推送，并给出 old / new。 比如竞品把价格从 $19.99 改成 $29.99 —— 条目还是那条，别的工具判定「无变化」。

支持哪些 Feed 格式？

RSS 2.0（含 RDF 变体）、Atom 1.0、JSON Feed 1.1，提交地址后自动识别，无需指定。 实测覆盖 GitHub Releases、Hacker News、Ars Technica、NASA、Cloudflare Blog、 人民网、中新网等国内外来源。

检查频率能自己定吗？

可以，当前提供三档：15 分钟（900 秒）、1 小时（3600 秒）、6 小时（21600 秒）。 更激进的频率需要联系我们在更高档位中开放。

Webhook 怎么验证签名？

响应头带 x-feedwatch-signature，是按请求体计算的 HMAC-SHA256。 必须验签 —— 不验签的话，任何人都能伪造一条合法推送。 未配置 secret 时我们不会发送该头，客户端能明确区分「未配置」而非误以为已验签。

会限制请求频率吗？

会。/mcp 端点与监控点创建都有滑动窗口限流，避免单个 key 占满资源。 超出时会返回 429。具体额度当前按套餐档位设置，细节可在接入时确认。

数据存在哪里？会保存 feed 内容吗？

快照只保存计算 diff 所需的字段与哈希，用于比对，不存储完整正文原文。 监控点配置与状态在当前版本存于内存，服务重启后清空 —— 这是测试期的已知限制， 正式版本会迁移到持久化存储。

能监控哪些地址？会不会被用来扫内网？

出于安全考虑，只允许抓取公网地址。DNS 解析到私有网段、回环地址或云元数据地址 （如 169.254.169.254）的请求会被直接拒绝。重定向也会逐跳重新校验。 提交的 webhook 地址走同一套防护。

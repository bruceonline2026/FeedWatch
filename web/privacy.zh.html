隐私政策

简短版：API Key 只存哈希，Feed 内容在内存中处理、从不落盘，我们不出售也不与任何人共享你的数据。

最后更新：2026-10-16

我们实际保留什么：API Key 的 SHA-256 哈希、你提供的监控点URL、你的套餐等级、以及抓取失败时的错误信息。全部在服务器内存中。

存什么、存多久

数据形式保留时长
API Key仅 SHA-256 哈希 —— 明文只在创建时显示一次，此后再不写入任何地方直到你删除该 Key，或服务重启
监控点 URL明文，存于内存直到你删除该监控点
Feed 内容从不存储 —— 内存中解析、比对后立即丢弃数秒
检出的变更投递到你的 webhook 后即丢弃数秒
错误信息明文，存于内存（如「上游返回 HTTP 403」）直到下次成功检查
服务器访问日志请求路径、状态码、IP、时间戳 —— 不含请求体按主机配置

我们额外记录了什么（计数，不含你的数据）

为了让产品能用下去，我们需要知道「有多少人在用、有多少人卡住了」。 所以会记录一些纯计数类信息：

记什么形式为什么
领了 API Key 的动作事件类型 + 时间 + Key 的随机 id知道有多少用户在用
建了监控点的动作同上 + 当前已有几个知道功能是否被真正使用
撞到 5 个上限同上 + 当时已有几个知道有多少人需要更多配额
建监控点失败失败分类（非内容，如「不是 feed」）发现产品缺口

这些记录里没有：

· 你的监控点 URL
· feed 标题 / 正文 / 作者
· 检出的变更内容
· 你的邮箱地址
· API Key（明文或哈希）
· 请求头、浏览器指纹、来源 IP

也就是说：我们知道「有 3 个人卡在了上限上」， 但不知道那 3 个人是谁、监控的是什么网站。

为什么值得说明

市面上的监控工具普遍会埋第三方追踪器。我们不用 —— 所以这个「我们额外记了什么」的清单，就是全部内容， 没有藏在别处的第二套统计。你可以要求我们删掉你的记录。

三点值得单独说明

你的 API Key 从不以明文存储

创建 Key 时，响应里会包含它，且仅此一次。 之后我们只保存 SHA-256(key) 并据此比对。 即使有人获得服务器内存的完整读取权限，也无法从我们持有的数据反推出你的 Key。

代价也要说清楚：我们无法帮你找回丢失的 Key， 也不会把它再发一封邮件给你。丢了就重新创建一把。

Feed 内容不落盘

抓取时，响应体在内存中解析、与上一轮快照比对，然后丢弃。 没有数据库、没有文件、没有缓存 —— 我们不会在暗中构建互联网的影子副本。

监控点不扛重启 —— 这有两面性

因为一切都在内存中，服务重启会清空所有监控点与 Key。 这对隐私是好事，对可靠性是坏事。持久化存储在下一版本； 到时会先通知你，再变更本政策。

会传给第三方什么

对象何时传什么
你监控的 Feed 站点每次检查标准 HTTP 请求元信息 —— 你的 API Key 绝不转发出去
你的 webhook 地址检出变更时变更内容 + HMAC 签名
Slack / Discord你启用后仅你配置的那条消息

我们不使用广告网络、分析追踪器或第三方数据 broker。

支付

支付由支付机构全程处理。我们只收到「扣款成功」与「购买了哪个套餐」的确认， 绝不接触你的完整卡号或银行信息。

安全措施

  • Webhook 带 HMAC-SHA256 签名，你可验证来源并拒绝伪造内容。
  • Node 服务只监听 127.0.0.1；TLS 在反向代理终结。
  • 所有出网抓取都经过 SSRF 防护（DNS 钉IP + 逐跳重校验）， 服务无法被用来探测内网或云元数据地址。
  • Feed 响应体上限 10 MB，XML 实体展开有结构性约束。

你的权利

你可以随时：

  • 删除你创建的任何监控点
  • 询问我们持有你哪些数据 —— 答案会很短，因为确实没多少
  • 要求删除你的账号数据

由于一切在内存中、没有数据库，删除账号实质上就是「重启 + 让你的 Key 失效」。 你提出请求后我们会为你执行。

未成年人

FeedWatch 是开发者工具，不面向 16 岁以下人群，我们不故意收集未成年人信息。

政策变更

实质性变更会在本页更新并标注日期，不会追溯适用到旧版政策下已收集的数据。

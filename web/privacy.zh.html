隐私政策

简短版：API Key 只存哈希，从不存明文。为了告诉你「哪个字段、从什么变成什么」，我们会在服务器磁盘上保留 feed 条目的明文副本用于比对—— 这是这个能力的必要条件。我们不出售、不与任何人共享、不做画像、不做跨客户关联。

最后更新：2026-10-17

我们实际保留什么：你的 API Key 的 SHA-256 哈希、你提供的监控点 URL 与名称、你监控的 feed 条目标题与正文（明文）、错误信息，以及你申请 Key 时使用的邮箱域名。除 API Key 明文外，这些都存放在服务器磁盘上，文件权限仅服务进程可读。

完整、机器可读的清单：GET /v1/data-handling（公开、无需鉴权）。该端点由自动化测试与实际落盘字段双向核对；本页与该端点如有不一致，以端点为准并会修正本页。

为什么 feed 条目要存明文副本？因为我们承诺的核心能力是 「告诉你哪个字段从什么变成了什么」，而不是只说「有更新」。 要输出「标题从 A 变成了 B」，磁盘上必须同时存在 A 和 B。 如果只存哈希，哈希不可逆，我们只能告诉你「变了」，无法告诉你变成了什么—— 那就退化成了各家监控工具都有的「这页变了」提示器，也就不再是我们在卖的东西。

这些内容本身是公开的订阅源，地址是你给我们的。我们缓存它只是为了给你算差异。

我们额外记录了什么（计数，不含你的数据）

为了让产品能用下去，我们需要知道「有多少人在用、有多少人卡住了」。 所以会记录一些纯计数类信息：

记什么形式为什么
领了 API Key 的动作事件类型 + 时间 + Key 的随机 id知道有多少用户在用
建了监控点的动作同上 + 当前已有几个知道功能是否被真正使用
撞到 5 个上限同上 + 当时已有几个知道有多少人需要更多配额
建监控点失败失败分类（非内容，如「不是 feed」）发现产品缺口

这些统计记录里没有：

· 你的监控点 URL
· feed 标题 / 正文 / 作者
· 检出的变更内容
· 你的邮箱地址
· API Key（明文或哈希）
· 请求头、浏览器指纹、来源IP

也就是说：我们知道「有 3 个人卡在了上限上」， 但不知道那 3 个人是谁、监控的是什么网站。

请注意区分：上面这张表讲的是 运营统计日志（events-*.jsonl），它确实只有聚合计数。 但你的监控点与 feed 内容确实存放在磁盘上—— 见上面「存什么、存多久」那一张表。这两件事不冲突： 统计日志不记录你的数据，但服务本身为了给你算差异而缓存了你的数据。

为什么值得说明

市面上的监控工具普遍会埋第三方追踪器。我们不用 —— 所以这个「我们额外记了什么」的清单，就是全部内容， 没有藏在别处的第二套统计。

三点值得单独说明

你的 API Key 从不以明文存储

创建 Key 时，响应里会包含它，且仅此一次。 之后我们只保存 SHA-256(key) 并据此比对。 即使有人获得我们服务器数据文件的完整读取权限，也无法从我们持有的数据反推出你的 Key 明文。

代价也要说清楚：我们无法帮你找回丢失的 Key， 也不会把它再发一封邮件给你。丢了就重新创建一把。

我们缓存了什么、为什么，以及我们不做什么

为了提供「字段级变更」——也就是告诉你标题从 A 变成了 B，而不只是「有更新」—— 我们必须在磁盘上保留上一次的 feed 内容用于对比。 这是这个能力的必要条件，不是我们的选择。

我们不做什么：

  • 不分析、不转卖、不与任何人共享这些内容
  • 不做用户画像，不做跨客户关联
  • 推送给你时只发哈希与长度，不发正文全文
  • 不使用广告网络、分析追踪器或第三方数据 broker

这些内容本身是公开的订阅源，地址是你给我们的。我们缓存它只是为了给你算差异。

保留多久、怎么删

你的数据随监控点一直保留，期间每轮检查覆盖一次基线。 删除监控点时，其对应的 feed 内容会一并删除。

你可以随时自己做到：

  • 查看服务是否在正常工作 —— 调 GET /v1/monitors， 每个监控点都会返回 last_checked_at、last_check_ok、 last_error、next_check_at。 last_check_ok 为 true 且 last_error 为 null，就说明最近一次检查成功了。
  • 删除某个监控点及其缓存的 feed 内容 —— DELETE /v1/monitors/{id}

⚠️ 需要人工处理的两件事，我们不假装能自助：

  • 吊销一把 Key —— 目前没有自助端点，请发邮件给我们。
  • 删除你的全部账号数据（包括 API Key 哈希与邮箱域名）—— 目前只能由我们人工执行，请发邮件给我们，我们会在 1 个工作日内处理。

支付

支付由支付机构全程处理。我们只收到「扣款成功」与「购买了哪个套餐」的确认， 绝不接触你的完整卡号或银行信息。

安全措施

  • Webhook 带 HMAC-SHA256 签名，你可验证来源并拒绝伪造内容。
  • Node 服务只监听 127.0.0.1；TLS 在反向代理终结。
  • 所有出网抓取都经过 SSRF 防护（DNS 钉IP + 逐跳重校验）， 服务无法被用来探测内网或云元数据地址。
  • Feed 响应体上限 10 MB，XML 实体展开有结构性约束。

你的权利

你可以随时：

  • 自助删除你创建的任何监控点（DELETE /v1/monitors/{id}）—— 其缓存的 feed 内容会一并删除
  • 自助查看服务状态（GET /v1/monitors）—— 每个监控点的上次检查时间、是否成功、错误信息
  • 查询我们持有你哪些数据 —— GET /v1/data-handling 列出全部字段名，你也可以发邮件问我们具体内容
  • 要求删除你的账号数据 —— 这一项目前需要人工处理，见上节

⚠️ 我们如实说明当前能力的边界：目前没有「一键删除全部数据」的自助端点， 也没有自助吊销 Key 的端点。这两项都需要发邮件由我们人工执行。 我们把它写在这里，而不是让你以为点一下就能删干净。
